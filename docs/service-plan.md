# JeGap (제값) 서비스 기획서 — 1차 공개 (초안)

> 상태: 초안 (2026-11-15) · 대상: V4 1차 공개 · 기술 설계는 [portfolio-architecture.md](../portfolio-architecture.md) Phase 4-4 · 12장

## 1. 한 줄 정의

**서울 아파트 매물의 호가를 넣으면, 실거래로 학습한 모델이 적정가 범위와 판정, 그 근거를 보여주고 AI가 설명 · 상담하는 서비스.**

## 2. 누구의, 어떤 순간의 문제인가

| 구분 | 내용 |
|---|---|
| 주 사용자 | 서울 아파트 매수를 검토하는 실수요자 (첫 집 · 갈아타기, 30~40대) |
| 보조 사용자 | 내 집을 얼마에 내놓을지 가늠하려는 매도 검토자 |
| 그 순간 | 매물 사이트나 중개사무소에서 호가를 보고 "이 가격이 맞나" 판단해야 할 때 |
| 지금의 대안 | 같은 단지 실거래 목록을 직접 훑어보거나, 중개사 · 지인 말에 기댄다 |
| 불편 | 층 · 면적 · 거래 시점이 달라 직접 비교가 어렵고, 최근 시세 변화를 보정하기 어렵다. 판단 근거를 설명해 주는 곳이 없다 |

## 3. 핵심 질문과 약속

- 핵심 질문: **"이 호가, 제값인가?"**
- 약속
  1. 숫자 하나가 아니라 **범위**로 보여준다 (모델 오차를 숨기지 않는다).
  2. 판정마다 **근거**(같은 단지 최근 거래, 시세 흐름)를 같이 보여준다.
  3. 모델이 약한 집은 **판정하지 않고 참고용**이라고 말한다.

## 4. 1차 범위

| 포함 | 제외 (2차 이후) |
|---|---|
| 단지 검색 · 단지 분석 페이지 | 로그인 · 관심단지 · 알림 · 저장 검색 |
| 호가 입력 판정 (면적 · 층 · 호가) | 저평가 스크리너 · 단지 비교 · 지도 |
| 지역 흐름 (구 4주 흐름 순위 · 권역 수급 · 정책 타임라인) | 오피스텔 · 빌라 등 다른 주택 유형 (V6) |
| AI 리포트 · 상담 (도구 숫자 근거, 정책 RAG) | 유료 기능 |
| 대상: **서울 아파트만** (화면에 명시) | 서울 밖 지역 (V5: 수도권 → 광역시 · 전국) |

## 5. 사용자 흐름

1. 단지 이름 · 주소로 검색
2. 단지 분석 페이지: 면적별 적정가 범위, 최근 거래, 시세 흐름, 단지 태그
3. 면적 · 층 · 호가 입력 → 판정 카드 (범위 안 / 다소 높음 / 높음 / 다소 낮음 / 낮음 / 참고용) + **적정가가 나온 과정 설명**: 직전 거래 → 구 시세 변화 → 모델 보정 → 적정가 · 범위와 호가 차이(+x%)
4. "왜 이렇게 나왔어?" → AI가 같은 숫자를 근거로 설명, 추가 질문 (대출 · 규제는 출처와 함께)

## 6. 화면 구성

| 화면 | 보여줄 것 | 근거 데이터 |
|---|---|---|
| S1 검색 | 단지명 · 주소 자동완성, 최근 많이 본 단지 | 단지 테이블 |
| S2 단지 분석 | 면적별 적정가 **범위**(중심값은 작게), 같은 단지 최근 거래 5건, 구 4주 흐름 순위, 단지 태그(대단지 · 신축 · 역 출입구 거리 등) | 11 매달 재학습 예측 · 80% 범위, 31 흐름 표, 21 태그 |
| S3 호가 판정 | 판정 문구, 범위 막대 위 호가 위치, **설명 단계(직전 거래 → 구 시세 변화 → 모델 보정 → 적정가, 호가 +x%)**, 근거 거래, 안내(적정가 기준일 · 모델 학습은 약 2개월 전 거래까지, 같은 단지 거래 · 구 시세는 매주 반영 · 실거래 기준 적정가와 비교) | 11 범위 · 판정 규칙 |
| S4 AI 상담 | 리포트(요약 · 가격 요인 · 리스크), 대화, 정책 답변의 출처 링크 | ai-service 도구 결과만 |

## 7. 판정 규칙과 표현

- 판정 = 호가와 적정가의 비율이 80% 범위 안인지, 밖이면 범위 반폭 대비 얼마나 벗어났는지 (11 등급 규칙과 같은 계산).
- 범위는 매달 최근 3개월 모델 오차로 다시 만든다. 구간 = 기존/신규 단지 × 가격대 × **단지 최근 흐름** (`r11_interval5`).
- **참고용 (판정 안 함):** 신규 단지, 같은 면적 직전 거래가 1년 넘었거나 없는 집 (2026-11-20 결정) — 범위를 보완해도 실제 포함률이 67.4%라 판정이 자주 틀린다.
- **호가 주의:** 모델은 실거래가로 학습했다. 호가는 보통 실거래보다 높게 나오므로 문구는 "실거래 기준 적정가보다 높은 편"처럼 비교 기준을 밝힌다.
  - 확인 (2026-11-25, 손으로 캡처한 KB부동산 시세 칸 28개 단지, [asking-price-check.md](asking-price-check.md) §8): 매물평균가는 적정가보다 **중앙 3.8% 높았지만 28개 중 21개가 80% 범위 안**, "다소 높은 편" 이상 21.4% → 판정이 "높음"으로 쏠리지 않아 **판정 단계를 유지하고 설명을 함께 보여 준다** (사전 기준: 50% 이상이면 "+x%" 중심으로 변경)
  - 모델 적정가와 단순 계산(직전 거래 × 구 시세 변화)의 차이가 10% 넘는 단지가 4개 → 설명에 "모델 보정" 단계를 넣어 직전 거래와 왜 다른지 보여 준다
- **쓰지 않는 표현**
  - "감정가 · 감정평가": 「감정평가 및 감정평가사에 관한 법률」 제2조는 감정평가를 "토지등의 경제적 가치를 판정하여 가액으로 표시하는 것"으로, 제49조 제2호는 감정평가법인등이 아닌 자의 감정평가업(타인 의뢰 · 보수)을 처벌한다 → **"모델 추정 적정가"**로 표기 (조문 확인 결과이며 법률 자문 아님)
  - "매수 추천 · 지금 사세요 · 오를 것": 투자 권유 · 미래 단정 금지 (12장 Guardrail)
  - "저평가 단지": 31에서 단지 단위 저평가는 오히려 덜 올랐다 → 개별 호가 · 거래에 대한 사실만 표현

## 8. AI 상담 원칙 (12장 요약)

- 숫자는 도구(적정가 · 범위 · 흐름 · 근거 거래) 결과만 쓰고, 도구에 없는 숫자는 만들지 않는다 (답변 숫자 = 도구 결과 코드 검증).
- 모르는 것 · 참고용인 집은 그렇게 말한다.
- 투자 판단 요청("살까요?")에는 판단 대신 확인할 점(근거 거래 · 범위 · 대출 조건)을 안내한다.
- 대출 · 규제 답변은 정책 문서 출처를 붙인다.
- 비용: 로그인이 없으므로 세션 · IP 단위 호출 한도, 같은 단지 · 월 리포트는 캐시.

## 9. 차별점

| 기존에 흔한 방식 | JeGap |
|---|---|
| 실거래 목록 · 시세 그래프를 보여주고 판단은 사용자에게 | 사용자가 보는 **그 호가를 직접 판정** |
| 숫자 하나 | **범위 + 근거 + 참고용 표시** (모델 오차를 공개) |
| 일반 챗봇 | 모델 숫자만 근거로 답하는 상담, 정책은 출처 |

## 10. 성공 지표 (데모 기준)

| 지표 | 정의 | 목표 (초안) |
|---|---|---|
| 판정 완료율 | 단지 페이지 방문 중 호가 판정까지 간 비율 | 측정 시작 후 정함 |
| AI 숫자 정확도 | 평가 세트에서 답변 숫자 = 도구 결과 | 100% (불일치는 재생성 · 차단) |

## 11. 위험과 대응

| 위험 | 대응 |
|---|---|
| 법적: 감정평가 해석 | 표현 제한(7장), 무료 · 통계 추정임을 명시. 유료화 · 개별 의뢰형 기능 전에는 전문가 검토 |
| 신뢰: 잘못된 판정 | 범위 중심 표시, 참고용 규칙, 근거 거래 공개, 매달 포함률 모니터링 |
| 상승장 과소추정 (Test 평균 1.8% 낮게) | 범위가 과거 오차 분포로 만들어져 판정에 반영됨. 중심값만 크게 보이지 않게 |
| LLM 비용 · 장애 | 호출 한도 · 캐시 · 일 · 월 비용 한도, 장애 시 ML 카드만 표시 |
| 데이터 지연 | 실거래 신고 시차 · 공표 시차를 화면에 표시 ("모델 학습은 약 2개월 전 거래까지, 같은 단지 거래 · 구 시세는 매주 반영") — 적정가는 매주 금요일 다시 계산 (v4-design 2-1 주간 재예측 백테스트, 2026-11-25) |
| 개인정보 | 로그인 없음. 입력한 호가는 개인 식별 정보 없이 판정 이벤트로 12개월 보관(입력란에 안내), 대화 원문은 30일 (v4-design 6-6) |

## 12. 검증 계획

1. 화면 초안(S2 · S3 · S4)을 만든다.
2. 대상 사용자 5명에게 과제를 준다: "관심 있는 단지의 매물 호가를 판정해 보고, 결과를 다른 사람에게 설명해 보세요."
3. 본다: 판정 문구를 맞게 이해했는지, 범위를 이해했는지, 참고용을 신뢰했는지, AI 답변을 믿었는지.
4. 문구 · 흐름을 고친 뒤 개발 범위를 확정한다.
